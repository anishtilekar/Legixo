## Conclusion

**The bands overlap.** The lowest answerable question scores 0.8383, while the highest out-of-corpus question scores 0.8719 — the out-of-corpus set sits *inside* the answerable range. This is the E5 score compression the design anticipated: on a corpus this small every chunk is somewhat similar to every query.

**No absolute threshold can separate answerable from unanswerable questions here.** Any floor high enough to catch the out-of-corpus cases would also refuse legitimate questions (anything above 0.8383 causes false refusals).

Margins overlap too (answerable 0.0372–0.0992 vs out-of-corpus 0.0152–0.0722), so a relative margin test does not rescue it either.

**Decision: `RELEVANCE_FLOOR` stays at 0.75** — deliberately well below the observed answerable minimum (0.8383) so it can never cause a false refusal. It is a coarse backstop for genuinely degenerate retrieval (empty index, wrong-language query), *not* the relevance decision. The LLM grader in `grade_context` makes the real judgement, and the out-of-corpus eval cases are what verify it.

Retrieval recall is 15/15 — the correct source is essentially always retrieved, which confirms failures are grading failures, not retrieval failures.
